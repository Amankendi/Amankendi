# ALKENDI Digital Sovereignty Standard | معيار السيادة الرقمية
**Policy ID:** ALKENDI-SOVEREIGNTY-001  
**Version:** 1.0  
**Approved by:** Project owner, 2026-11-02  
**Scope:** AMAN Product Lifecycle (APLC), AMAN Office, ALKENDI LAB, owned initiatives, prototypes, partner projects and client deliveries according to each project's actual ownership rights.

## المبدأ الإلزامي
لا يجوز أن يعتمد استمرار أي مشروع على وجود ChatGPT أو OpenAI أو نموذج ذكاء اصطناعي واحد أو مطوّر واحد أو حساب تشغيل لدى مزود واحد. يجب أن يتمكن المالك القانوني أو الجهة المستلمة، أو مطوّر مخوّل من طرفها، من تشغيل المشروع وصيانته واستعادة بياناته ونقله ضمن حدود الحقوق والعقود والقانون.

**صياغة قبول:** لا يُعلن المشروع «مكتمل التسليم وقابلًا للتشغيل المستقل» قبل وجود حزمة تسليم H01–H10 وأدلة قبول قابلة للتكرار؛ أي استثناء تجريبي يجب أن يحمل حالة معلنة ويخضع لموافقة المالك.

## 1. ثلاث زوايا تصنيف مستقلة — لا تخلط بينها
لكل مشروع ثلاثة حقول منفصلة، لأن «موقع ظاهر» لا يعني أن «الخدمة تعمل»، والاستضافة الخارجية لا تعني بالضرورة «كود مغلق».

**أ. نضج الوظائف / Lifecycle**
- PRODUCTION_VERIFIED — مسار إنتاج فعلي اختُبر بدليل (الدخول، البيانات، الصلاحيات، البريد/الدفع عند وجودهما).
- PUBLIC_ONLINE_UNVERIFIED — صفحة عامة متاحة لكن لم يُختبر المسار التشغيلي الكامل.
- BETA / PILOT — نسخة تجربة بمستخدمين/حدود معلنة، دون ادعاء جاهزية تجارية.
- PROTOTYPE / PREVIEW — نموذج، واجهة، أو بناء تجريبي.
- PAUSED / INACTIVE — توقف منشور أو قاعدة/خدمة غير فعّالة.
- IDEA / PLANNED — تصور أو مواصفات بلا تطبيق إنتاجي مثبت.
- UNKNOWN — لا توجد أدلة كافية.

**ب. مسؤولية الاستضافة والبيانات / Provider**
- SELF_CONTROLLED_ACCOUNT — حساب يسيطر عليه المالك مع اعتماد بنية مزود (Cloudflare, Vercel, Supabase, إلخ).
- PROVIDER_MANAGED_PLATFORM — منشئ تطبيقات/خدمة مُدارة يتولى فيها المورد الخادم والبيانات.
- CLIENT_OR_PARTNER_CONTROLLED — حساب جهة أخرى مع إثبات نطاق التفويض.
- UNVERIFIED — الاستضافة أو الملكية غير مثبتة.

**ج. ملكية المصدر وقابليته للنقل / Portability**
- PORTABLE_TESTED — شيفرة ومهاجرات وبيانات وإجراءات خارجية، استعادة ونشر اختُبرا لدى مزود بديل.
- SOURCE_RETAINED_NOT_MIGRATION_TESTED — شيفرة/وثائق محفوظة، لكن النقل لم يُختبر أو قاعدة الإنتاج غير مستعادة.
- VENDOR_EXPORT_LIMITED — تصدير جزئي أو نسخة كود غير قابلة لتشغيل مستقل دون إعادة تطوير.
- READY_MADE_SERVICE / TEMPLATE — خدمة جاهزة أو قالب/منشئ تطبيقات مُدار؛ يجب تحديد التراخيص وحدود النقل.
- NO_EXPORT_VERIFIED / UNKNOWN — لا دليل كافٍ أو لا يوجد تصدير موثق.

## 2. حزمة السيادة — امتداد H01–H10
إلزاميات حزمة التسليم المقررة في `docs/06_AMAN_BUILD_PERMANENT_HANDOVER_20261019.md` باقية دون تخفيف:
- **H01:** الشيفرة الكاملة الواقعة ضمن حقوق المالك، lockfile، نسخة إصدار ثابتة وتعليمات البناء.
- **H02:** خارطة النطاقات وDNS والحسابات والاستضافة والبيئات والنسخ والنشر والتراجع.
- **H03:** تصدير البيانات بنسق مفتوح + الجداول/المهاجرات + تعليمات استيراد آمنة.
- **H04–H05:** صلاحيات الإدارة ودليل العمليات من دون محادثة أو مساعد.
- **H06:** أمن وخصوصية وحقوق ومخاطر وحماية بيانات المستخدمين.
- **H07–H08:** رسوم متكررة ومالك كل حساب والتراخيص والحقوق وسند تسليم.
- **H09:** اختبارات حقيقية لكل مسار أساسي وحدود إطلاق موثّقة.
- **H10:** نسخ احتياطية مستقلة ومشفرة ومختبرة عبر استعادة فعلية.

## 3. شروط اختبار الاستقلال
اختبار الاستقلال مقبول فقط إذا استطاع مطوّر مؤهّل **لم يبن المشروع**، بناء على صلاحيات ممنوحة من المالك:
1. استنساخ الإصدار المثبّت، تثبيته وبناؤه دون الرجوع إلى محادثات ChatGPT.
2. تشغيل بيئة استعراض منفصلة دون مشاركة أسرار أو بيانات إنتاج حساسة.
3. استيراد نسخة احتياطية معقّمة والتحقق من الأدوار والبيانات.
4. نشر نسخة مستقلة في حساب المالك أو في حساب مزود بديل، وإثبات القدرة على توجيه النطاق بعد موافقة المالك.
5. إجراء تحديث صغير والتراجع عنه، وتوثيق الاختبار بالتاريخ والمسؤول والنتيجة.

**READY في منصة النشر لا يساوي PRODUCTION_VERIFIED، وعرض الواجهة لا يثبت دورة دفع أو بريد أو صلاحيات.**

## 4. اعتماد الموردين الخارجيين والخدمات الجاهزة
أي مشروع مبني على منصة مثل Whacka أو خدمة Sites مُدارة أو منشئ تطبيقات:
- سجّل اسم المورد، صاحب الاشتراك، خطة الأسعار والتجديد، بلد تخزين البيانات، وشروط الترخيص.
- اختبر هل يتيح تصدير المصدر والبيانات **واستعمالهما خارج المورد فعلًا**؛ وجود زر Code Export لا يثبت إمكانية الاستضافة المستقلة.
- إن كان المصدر المعاد تصديره لا يعمل وحده، صنّف `VENDOR_EXPORT_LIMITED` حتى يثبت عكس ذلك.
- لا تنقل سجلات DNS أو الهوية أو المستخدمين قبل اختبار الاستعادة وموافقة صاحب المشروع.

## 5. سياسة الاستمرارية والاعتماد
- الموقع يعمل بوظائفه الأساسية حتى إن لم تتوفر واجهة OpenAI أو نموذج ذكاء اصطناعي؛ ميزات AI اختيارية أو لها بديل معلوم، ويُعلن التعطل عند فقدها.
- يمنع تخزين بيانات الدخول والأسرار في المستودع أو تقارير التدقيق العامة؛ خزينة مشفرة، MFA، وحساب استرداد مستقل.
- لا يفترض وجود نسخ احتياطية لمجرد أن المزود يُجريها؛ يلزم تصدير مستقل واختبار استعادة مؤرخ.
- ملفات العملاء ومشاريع الجهات الأخرى تبقى تحت حقوق وملكية الجهة المعنية؛ لا تجمع البيانات أو الأسرار بين المشاريع دون تفويض.
- كل خدمة مدفوعة جديدة أو ترقية أو نقل أو تغيير إعدادات أمنية عالية التأثير أو نشر إنتاجي يحتاج موافقة منفصلة صريحة، حتى لو كانت سياسة السيادة معتمدة.
- يبقى التقييم من مصادر عامة وملفات GitHub وتقارير مزوّد الخدمة **تدقيقًا أوليًا** ما لم يثبت اختبار يدوي/آلي شامل.

## 6. سجلات المراجعة
حافظ في سجل خاص غير منشور علنًا على أعمدة:
`project_id | owner | public_url | source_repository | host_provider | database_provider | operational_state | evidence_level | source_portability | managed_or_ready_made | payments | email | backup_status | restore_test_date | H01-H10 | risk | decision | next_action | reviewed_at`.

**مبدأ الخصوصية:** التقارير التفصيلية عن مشاريع العملاء والحسابات الخاصة تُحفظ في مساحة خاصة، وليس في مستودع الحوكمة العام.

## 7. بوابة الاعتماد في APLC
`DISCOVER → CLASSIFY → DESIGN → BUILD → TEST → RECOVER → HANDOVER → RELEASE → MONITOR`

يجب أن يتضمن كل قرار إطلاق: وظيفة تشغيلية مثبتة، حالة المزوّد/القالب، سند ملكية الشيفرة أو الترخيص، اختبار استعادة، وثائق H01–H10، تاريخ اعتماد وموافقة صاحب القرار.

**Outcome labels:** DONE / TESTED / FAILED / BLOCKED / NEXT. No unverified claims.
